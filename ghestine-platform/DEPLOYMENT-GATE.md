# دروازهٔ ایمنی استقرار دیجی‌بایل پی

## محدودهٔ این شاخه

- مخزن: `digibile/vamcity`
- شاخهٔ ایزوله: `import/ghestine-platform-2026-10-26`
- سورس بسته: `ghestine-platform/source/all3/`
- آرشیو اصلی ورودی: `ghestine-platform/ghestine-all3.zip`
- مقصد برنامه‌ریزی‌شده: `digibail.ir`

این شاخه برای بستهٔ دیجی‌بایل پی است. آن را با `main` ادغام نکنید و فایل‌هایش را به مسیرهای Roofixo/VamCity یا Sookar/NAF کپی نکنید.

## وضعیت اعتبارسنجی

گردش‌کار GitHub Actions شمارهٔ [40287463793](https://github.com/digibile/vamcity/actions/runs/40287463793) با موفقیت آزمون‌های آرشیو ZIP، صفحات ضروری، نحو Bash، HTML/JavaScript، برند و مسیرها، بررسی فقط‌خواندنی سایت زنده و ساخت Artifact را گذرانده است.

Artifact بررسی‌شده: `digibail-pay-release`  
SHA-256 گزارش‌شده برای ZIP انتشار: `d9c3d13dd1c3771a0a58a015449d34c118c3ea6805901e1fb32651eb0270c3cb`

این نتیجه فقط صحت بسته‌بندی و آزمون‌های تعریف‌شده را نشان می‌دهد؛ **تأیید build بک‌اند، اتصال دیتابیس، یا استقرار روی سرور نیست.**

## موانع قبل از استقرار

بررسی قبلی سایت زنده این نتایج را ثبت کرده است:

- مسیرهای `/login.html`، `/register.html`، `/profile.html` و `/admin.html` پاسخ 404 داده‌اند.
- `/api/v1/security/captcha` و مسیرهای درخواست/تأیید OTP پاسخ 404 داده‌اند.
- `/api/v1/Auth/me` پاسخ 401 داده است؛ این پاسخ بدون نشست معتبر به‌تنهایی سلامت یا خرابی کامل احراز هویت را ثابت نمی‌کند.
- بستهٔ ورودی شامل فایل کامل پروژهٔ .NET، یعنی `.sln` و `.csproj`، نیست.
- نصب‌کننده‌ها به ساختار پروژهٔ موجود و مسیرهای مشخصی مانند `src/Ghestine.API` و `src/Ghestine.Infrastructure` وابسته‌اند.

## دروازه‌های اجباری

تا وقتی همهٔ موارد زیر تأیید نشده‌اند، نصب‌کننده‌ها و مایگریشن دیتابیس اجرا نشوند:

1. مسیر واقعی اکانت مالک `digibail.ir` و document root از DirectAdmin تأیید شود.
2. سورس کامل بک‌اند و فایل‌های پروژهٔ .NET واقعی پیدا و قابل build شوند.
3. قرارداد DTO و مسیرهای API احراز هویت/کپچا/OTP با کد بک‌اند تطبیق داده شوند.
4. بکاپ قابل‌بازیابی از فایل‌های فعلی و بکاپ معتبر دیتابیس تهیه و بررسی شود.
5. برنامه در مسیر مجزای متعلق به اکانت `digibail.ir` آماده و با آزمون‌های سلامت بررسی شود.
6. تغییر مسیر دامنه فقط پس از موفقیت آزمون‌های برنامه و تأیید rollback انجام شود.

## قواعد ممنوع

- اجرای `install-all.sh` یا `dotnet ef database update` پیش از عبور از دروازه‌های بالا.
- جایگزینی کل `public_html` یا حذف فایل‌های ناشناختهٔ موجود.
- استفاده از مسیرها، کانتینرها، دیتابیس‌ها، secrets یا فایل‌های اکانت‌های دیگر.
- ثبت رمز، توکن، کلید خصوصی، کلید پیامک یا فایل‌های محیطی محرمانه در Git.
- اعلام «استقرار موفق» صرفاً بر اساس سبز بودن GitHub Actions.

**وضعیت فعلی: بسته در GitHub موجود و آزمون‌های بسته‌بندی موفق‌اند؛ استقرار سرور و سلامت بک‌اند هنوز تأیید نشده‌اند.**
