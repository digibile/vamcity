# طرح ادغام صفحه عمومی وام‌سیتی با سامانه واقعی موجود

وضعیت: **آماده بررسی؛ هنوز روی سایت اصلی منتشر نشده است.**

## هدف
یک وب‌سایت عمومی واحد در `https://roofixo.ir/` بسازیم که ظاهر جدید صفحه اصلی را حفظ کند، اما طرح‌ها، جزئیات، درخواست وام، ثبت‌نام و ورود را از سامانه واقعی وام‌سیتی استفاده کند. صفحه عمومی جداگانه‌ای که داده‌های ساختگی نشان بدهد جایگزین منطق قدیمی نخواهد شد.

## بررسی کد موجود در مخزن
- فایل‌های قدیمی رابط Vue در `wwwroot/ui/js/` وجود دارند؛ صفحه فهرست طرح‌ها از داده واقعی و فیلترهای سود، جریمه دیرکرد، سود زودکرد، سقف و دوره بازپرداخت استفاده می‌کند.
- صفحه جزئیات طرح، جزئیات واقعی طرح را از `loan/get/{customerCode}/{code}` دریافت می‌کند.
- دکمه ثبت درخواست در صفحه طرح، در صورت ورود کاربر، درخواست را با `member/userLoanRequest/create` ثبت می‌کند؛ در غیر این صورت به مسیر ثبت‌نام برنامه هدایت می‌شود.
- فرم سفارش خرید اقساطی، درخواست را به `CustomerOrder/create` می‌فرستد.
- API فهرست طرح‌ها `/Loan/List/100` در بررسی انتشار قبلی با پاسخ موفق و رکوردهای واقعی تأیید شده است.
- سورس بازیابی‌شده هنوز یک پورت لینوکسی کاملاً اعتبارسنجی‌شده محسوب نمی‌شود؛ بنابراین نباید منطق مالی، احراز هویت یا ارسال درخواست را صرفاً با ظاهر جدید جایگزین کرد.

## تجربه یکپارچه پیشنهادی
1. **صفحه اصلی:** طراحی فعلی، معرفی خدمات، محاسبه‌گر اقساط، طرح‌های فعال و فراخوان‌های اقدام.
2. **مشاهده طرح‌ها:** دریافت مستقیم از `/Loan/List/100`، حالت بارگذاری، خطا و حالت بدون طرح؛ بدون عدد یا طرح نمونه.
3. **جزئیات طرح:** بازکردن مسیر واقعی طرح با کد آن؛ نمایش شرایط و مدارک از API قدیمی.
4. **درخواست وام:** استفاده از گردش کار واقعی صفحه طرح و احراز هویت موجود، نه فرم نمایشی.
5. **ثبت‌نام و ورود:** حفظ صفحه‌های اصلی برنامه و اتصال دکمه‌ها به مسیرهای واقعی. مسیرهای Nginx که فعلاً `/login/` و برخی مسیرهای ورود/ثبت‌نام را به صفحه اصلی هدایت می‌کنند باید در مرحله انتشار به‌صورت حساب‌شده اصلاح شوند؛ در غیر این صورت دکمه‌ها به مقصد واقعی نمی‌رسند.
6. **ثبت سفارش خرید اقساطی:** اتصال فقط به `CustomerOrder/create` و نمایش پاسخ واقعی API.
7. **قالب و تنظیمات:** پنل مدیریت قالب فعلی باقی می‌ماند و از وب‌سایت عمومی جداست؛ تنظیمات ظاهری بعداً باید از تنظیمات معتبر سامانه خوانده شوند، نه از داده‌های ساختگی پنل.
8. **مسیرهای قدیمی:** پیوندهای قبلی طرح‌ها، ورود، ثبت‌نام و درخواست بررسی می‌شوند تا 404/ریدایرکت حلقه‌ای یا مسیر مرده باقی نماند.

## فایل پیش‌نمایش
`integration-proposal/public-site/index.html` یک پیش‌نمایش مستقل است. فهرست طرح‌ها را از API واقعی می‌خواند و برای هر طرح به صفحه جزئیات برنامه لینک می‌دهد. این فایل هنوز به مسیر صفحه اصلی سرور کپی نشده است.

## مواردی که پیش از انتشار باید تأیید شوند
- API فهرست طرح‌ها در مرورگر، با کوکی/بدون کوکی و روی HTTPS کار کند.
- مسیرهای واقعی ورود و ثبت‌نام با لینک‌های عمومی سازگار شوند.
- هر طرح به صفحه جزئیات معتبر برسد و فرم درخواست به همان API قدیمی وصل بماند.
- هیچ داده ساختگی، درخواست واقعی ناخواسته یا اطلاعات حساس در صفحه عمومی نمایش داده نشود.
- تست موبایل، RTL، خطاهای شبکه، لینک‌ها و پاسخ‌های 200/302/401/404 انجام شود.
- از فایل فعلی صفحه اصلی و تنظیمات Nginx پیش از انتشار نسخه پشتیبان گرفته شود و امکان بازگشت وجود داشته باشد.

## انتشار
**هیچ تغییری در سایت زنده با این پیش‌نمایش انجام نشده است.** پس از بررسی و تأیید، مرحله بعد شامل ادغام نهایی، اصلاح دقیق مسیرهای ورود/ثبت‌نام، اجرای تست‌ها و انتشار کنترل‌شده خواهد بود.
