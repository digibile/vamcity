# بسته مهاجرت VamCity

این پوشه محل متمرکز ابزارهای انتقال دیتابیس SQL Server به MariaDB است.

## مقصد مصوب
- SQL Server مبدأ: `vamcitydigibilepay`
- MariaDB مقصد: `vamcitydigibilepay`
- مقصد واحد است؛ نام‌های جانبی بکاپ‌ها به‌تنهایی مجوز ساخت دیتابیس مقصد جداگانه نیستند.

## فایل‌ها
- `sqlserver-inventory.sql`: استخراج متادیتای کامل جداول، ستون‌ها، کلیدها، روابط، ایندکس‌ها، viewها، routineها و triggerها.
- `migration-manifest.json`: اعداد و شواهد ثبت‌شده از بررسی قبلی بکاپ‌ها و وضعیت اعتبارسنجی.
- `../VAMCITY-SQLSERVER-TO-MARIADB-MIGRATION.md`: طرح مهاجرت و موانع شناخته‌شده.

## اجرای inventory روی SQL Server
اسکریپت SQL را در دیتابیس مبدأ اجرا و خروجی هر result set را به‌صورت CSV/JSON نگهداری کنید. این مرحله فقط خواندنی است و داده‌های عملیاتی را تغییر نمی‌دهد.

## اجرای انتقال
تا وقتی mapping نوع داده‌ها و برخورد نام جدول‌ها بررسی نشده، هیچ اسکریپت عمومی نباید روی دیتابیس عملیاتی اجرا شود. اجرای نهایی باید:
1. بکاپ معتبر از مقصد بگیرد.
2. فضای staging را کنترل کند.
3. تراکنش/بچ‌های قابل بازیابی داشته باشد.
4. identityها را حفظ کند.
5. تعداد ردیف، PK، FK و داده‌های مالی را پس از انتقال تطبیق دهد.

## اسرار و داده‌های مشتریان
مقادیر اتصال فقط از متغیرهای محیطی/Secret Store خوانده شوند. رمز، فایل .bak/.bacpac، dump حاوی داده شخصی یا اطلاعات مالی مشتریان نباید در مخزن عمومی commit شود. تغییر رمز پس از انتشار، نسخه‌های قبلی Git و cloneها را پاک نمی‌کند.

## وضعیت فعلی
این بسته ابزار و شواهد قابل دسترس را ثبت می‌کند. import واقعی به MariaDB هنوز تأیید نشده است.

## مانع فعلی اجرای سرور

اجرای GitHub Actions با شناسه `40992894723` در مرحله اعتبارسنجی SSH متوقف شد: secret با نام `DEPLOY_SSH_KEY` موجود است، اما `DEPLOY_HOST` و `DEPLOY_USER` خالی هستند. در نتیجه هیچ فرمانی روی سرور اجرا نشده و مرحله بررسی بکاپ‌ها skip شده است. تا زمان تکمیل همین دو مقدار در تنظیمات Secrets مخزن، ادامه اجرای سرور از طریق این workflow ممکن نیست. مقادیر اتصال را داخل فایل‌های مخزن یا متن workflow قرار ندهید.
